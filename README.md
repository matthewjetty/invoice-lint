# invoice-lint

A linter for invoice line item CSV exports. It checks the kind of thing that
usually only gets noticed when accounting asks why a total doesn't add up:
arithmetic that doesn't match, negative quantities, missing tax rates,
currency codes that are actually typos.

It reads a CSV, checks every row, and prints findings with the line number
they came from, the same way a compiler prints line numbers for syntax
errors.

## Why

Invoice line items get generated by whatever system produced them and then
get exported, re-exported, hand-edited in a spreadsheet, and imported
somewhere else. Along the way it's easy for `quantity * unit_price` to stop
matching `line_total`, or for a tax rate column to end up blank instead of
zero. Nothing crashes. The numbers are just quietly wrong until someone
reconciles them by hand.

## Expected CSV format

```csv
description,quantity,unit_price,tax_rate,line_total,currency
Consulting hours,10,150.00,0.08,1620.00,USD
Widget A,3,19.99,0.08,64.77,usd
Late fee,1,25.00,,25.00,USD
```

Required columns: `description`, `quantity`, `unit_price`, `line_total`.
`tax_rate` and `currency` are optional but their absence is flagged, since a
blank tax rate silently becomes 0 and a blank currency means nobody knows
what the numbers are denominated in.

## Usage

```sh
python -m invoicelint invoices/march.csv
```

Running the sample above in strict mode (the default) reports:

```
invoices/march.csv:3: error E009: currency 'usd' is not a 3-letter uppercase code
invoices/march.csv:4: error W001: tax_rate is missing, assuming 0
```

Row 3's arithmetic actually checks out (3 * 19.99 * 1.08 = 64.77), but the
currency code is lowercase, which is its own bug class: case-sensitive
downstream systems will silently treat `usd` as unknown rather than as USD.

Row 4's tax rate is blank rather than `0`. Strict mode treats that as an
error, because "missing" and "explicitly zero" are different facts and the
linter doesn't want to guess which one you meant.

If you're importing a messy export you don't control and just want the real
arithmetic errors, add `--lenient`:

```sh
python -m invoicelint --lenient invoices/march.csv
```

In lenient mode, missing tax rate and missing currency become warnings
instead of errors, and a small rounding tolerance is applied to the
arithmetic check. The exit code is non-zero only if there's at least one
error, so `--lenient` output can still fail a CI job when the numbers are
actually wrong.

## Exit codes

- `0`: no errors (there may still be warnings)
- `1`: at least one error was found

## What it checks today

- `description` is non-empty
- `quantity` and `unit_price` parse as numbers and aren't negative
- `line_total` parses as a number
- `tax_rate`, if present, parses as a number and isn't negative
- `currency`, if present, is a 3-letter uppercase code
- `line_total` equals `quantity * unit_price * (1 + tax_rate)`, within
  tolerance
